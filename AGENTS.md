# TroveCloud Frontend

## Stack

- React 19
- Vite
- TypeScript
- React Router 7
- TanStack Query
- React Hook Form + Zod
- Tailwind CSS 4
- shadcn/ui + Radix
- Vitest + React Testing Library + MSW

## Architecture

- Follow the existing flow: pages/components -> hooks -> api -> Axios client.
- Keep server state in TanStack Query rather than duplicating it in local component state.
- Keep reusable network calls in `src/api` and query/mutation behavior in hooks.
- Reuse existing shadcn/Radix primitives and project components before introducing new UI abstractions.

## Authentication and Navigation

- Authentication uses backend-managed cookies; do not introduce client-side auth token storage.
- Preserve `withCredentials: true` on the shared Axios client.
- For auth-state-changing flows, update/invalidate/refetch `["currentUser"]` before navigating to guarded routes.
- Preserve the existing logout/session cache-clearing behavior.

## Errors and Feedback

- Do not surface raw backend/server error messages directly to users.
- Prefer explicit backend error-code mapping and static fallback text.
- Use inline feedback for expected client/auth validation failures where the existing flow does so.
- Use `@/lib/toast`; do not import Sonner's `toast` directly in feature components.

## Dialogs and UI State

- Preserve the existing parent-conditional mount pattern for short-lived dialogs when the dialog should reset on close.
- Follow existing design tokens and component patterns before creating new variants.

## Testing

- Add behavior-focused tests for new logic where the surrounding codebase does so.
- Mirror source paths under `tests/`, e.g. `src/hooks/foo.ts` -> `tests/hooks/foo.test.ts`.
- Use Vitest/RTL/MSW patterns already present in the repo.

## Browser verification

For browser-visible changes:

1. If Playwright is already configured, prefer relevant existing Playwright tests.
2. Use meaningful assertions that verify the intended behavior.
3. Capture screenshots when visual correctness materially matters.
4. Use Playwright trace/report to investigate failures when needed.
5. Report exactly what was verified and what evidence passed.

If Playwright is not installed or configured, do not install or introduce it automatically. Use the project's existing verification methods, and suggest Playwright only when browser-level testing would provide clear value.

## Project Boundaries

- This repository is frontend-only.
- The backend lives in `D:\TroveCloud-Backend`; do not modify it from frontend work unless explicitly requested.

## Project Conventions

- Prefer a default export when a module exposes one clear primary function, value, type, or interface.
- Prefer inline named exports when a module exposes multiple public functions, values, constants, types, or interfaces; do not collect them in a trailing `export { ... }` block.
- Files generated by libraries or frameworks (e.g. shadcn components in `src/components/ui/`) keep their upstream export style.
- Preserve the existing `//* relative/path.ts[x]` file-path header convention when adding or moving source files.
- Run relevant tests, typecheck, and/or build checks before claiming a change is complete.
